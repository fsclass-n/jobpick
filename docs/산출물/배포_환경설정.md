# jobpick 배포 환경 설정

## 1. 구성 개요 (GitHub Secrets/Variables 미사용)

```plaintext
GitHub main push
  ├─ GitHub Actions CI (.github/workflows/deploy.yml): 변경 경로별 프런트 빌드 / 백엔드 기동·헬스체크
  ├─ Netlify (GitHub 연동, netlify.toml)  frontend/** 변경 시 빌드 ─→ https://jobpick.netlify.app  (데모)
  └─ Render  (GitHub 연동, render.yaml)
       ├─ jobpick      Static Site  frontend/** 변경 + CI 통과 시 ─→ https://jobpick.onrender.com
       └─ jobpick-api  Web Service  backend/**, rpa/**, requirements.txt 변경 + CI 통과 시 ─→ https://jobpick-api.onrender.com

브라우저(Netlify·Render 프런트) ──HTTPS + Authorization: Bearer──→ jobpick-api.onrender.com (CORS 허용)
```

- 배포 토큰·Deploy Hook을 GitHub에 저장하지 않습니다. Netlify·Render가 각자 GitHub 앱으로 저장소를 감시해 직접 빌드·배포합니다.
- 빌드 설정은 저장소 파일로 관리합니다: `netlify.toml`(Netlify), `render.yaml`(Render Blueprint).
- **CI 게이트**: Render는 `autoDeployTrigger: checksPass`로 GitHub Actions CI가 통과한 커밋만 배포합니다. Netlify는 자체 빌드가 실패하면 기존 배포를 유지합니다.
- **경로별 배포**: Netlify는 base 디렉터리(`frontend/`)에 변경이 없으면 빌드를 건너뛰고, Render는 `buildFilter.paths`로 거릅니다.
- **Netlify ↔ Render 연동**: 두 프런트 모두 `VITE_API_BASE_URL=https://jobpick-api.onrender.com`으로 직접 호출합니다.
  - Netlify 프록시는 26초 타임아웃이 있어 Render 무료 인스턴스 콜드스타트(최대 약 1분) 시 첫 요청이 실패하므로 사용하지 않습니다.
  - 토큰은 `Authorization: Bearer` 헤더로 보내 도메인이 달라도 쿠키 문제가 없습니다.

## 2. Netlify (프런트엔드 데모, jobpick.netlify.app)

**최초 1회 연결**: Add new project → Import an existing project → GitHub → `fsclass-n/jobpick` → 사이트 이름 `jobpick` → Deploy. 빌드 설정은 `netlify.toml`이 자동 적용되므로 화면 입력값은 비워 둡니다.

| 항목 | 값 (`netlify.toml`) |
|---|---|
| Base directory | `frontend` |
| Build command | `npm ci && npm run build` |
| Publish directory | `dist` |
| `NODE_VERSION` | `24` |
| `VITE_API_BASE_URL` | `https://jobpick-api.onrender.com` |
| `VITE_USE_MOCK` | `true` (1단계 데모) → 백엔드 연동 후 `false`로 수정해 push |
| SPA 라우팅 | `/* → /index.html 200` |

## 3. Render

**최초 1회 연결** (둘 중 하나)
- **Blueprint (권장)**: New → Blueprint → `fsclass-n/jobpick` 선택 → `render.yaml`의 두 서비스 확인 → `sync: false` 비밀값 입력 → Apply.
  - 같은 이름(`jobpick`, `jobpick-api`)의 서비스가 이미 있으면 Apply 전 화면에서 "기존 서비스 수정"인지 확인합니다. 새로 생성된다고 나오면 기존 서비스를 삭제 후 적용해야 `jobpick.onrender.com`, `jobpick-api.onrender.com` 주소를 그대로 씁니다.
- **기존 서비스 수동 설정**: 아래 표 값을 각 서비스 Settings에 입력하고 Auto-Deploy를 **After CI Checks Pass**로 설정합니다.

### 3-1. Static Site `jobpick` (jobpick.onrender.com)

| 항목 | 값 |
|---|---|
| Root Directory | `frontend` |
| Build Command | `npm ci && npm run build` |
| Publish Directory | `dist` |
| Auto-Deploy | After CI Checks Pass |
| Build Filters | Included paths `frontend/**` |
| Redirects/Rewrites | `/*` → `/index.html` (Rewrite) |
| 환경 변수 | `NODE_VERSION=24`, `VITE_API_BASE_URL=https://jobpick-api.onrender.com`, `VITE_USE_MOCK=false` |

### 3-2. Web Service `jobpick-api` (jobpick-api.onrender.com)

| 항목 | 값 |
|---|---|
| Runtime / Plan / Region | Python / Free / Singapore (TiDB `ap-northeast-1`과 가장 가까운 리전) |
| Root Directory | (비움, 저장소 루트) |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn backend.app.main:app --host 0.0.0.0 --port $PORT` |
| Health Check Path | `/api/health` |
| Auto-Deploy | After CI Checks Pass |
| Build Filters | `backend/**`, `rpa/**`, `requirements.txt`, `.python-version` |
| Python 버전 | 저장소 `.python-version`(`3.11`)으로 고정 (Render 기본값 3.14) |

| 환경 변수 | 운영 값 / 설정 방법 |
|---|---|
| `APP_ENV` | `production` |
| `CORS_ORIGINS` | `https://jobpick.netlify.app,https://jobpick.onrender.com` |
| `OAUTH_REDIRECT_BASE_URL` | `https://jobpick-api.onrender.com` |
| `USER_JWT_SECRET` / `ADMIN_JWT_SECRET` | Blueprint `generateValue`로 서로 다른 값 자동 생성 |
| `USER_JWT_EXPIRE_MINUTES` / `ADMIN_JWT_EXPIRE_MINUTES` | `120` / `30` |
| `ADMIN_LOGIN_MAX_FAILURES` / `ADMIN_LOGIN_LOCK_MINUTES` | `5` / `15` |
| `ADMIN_TOTP_ISSUER` | `jobpick` |
| `ADMIN_TOTP_ENCRYPTION_KEY` | 직접 입력: `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` |
| `DATABASE_URL` | 직접 입력: TiDB 접속 문자열 (`...:4000/jobpick?ssl_verify_cert=true&ssl_verify_identity=true`), TLS 오류 시 `&ssl_ca=/etc/ssl/certs/ca-certificates.crt` 추가 |
| `ADMIN_INITIAL_EMAIL` / `ADMIN_INITIAL_PASSWORD` | 직접 입력 (**Render에만**, 저장소·.env.example 금지) |
| `GOOGLE_*` / `NAVER_*` / `KAKAO_*` / `GEMINI_*` | 직접 입력 (로컬 `.env`와 동일 키, OAuth 콜백 URL은 5절) |
| `DATA_GO_KR_API_KEY` / `SEOUL_OPEN_API_KEY` / `WORK24_API_KEY` / `SARAMIN_ACCESS_KEY` | 직접 입력 (발급 후) |
| `STORAGE_BACKEND` | `local` (무료 인스턴스 디스크는 재배포 시 초기화 → 파일 업로드 구현 시 `bucket` 전환) |

- Playwright를 Render에서 실행하려면 Build Command에 `&& playwright install chromium`을 추가하고, 시스템 라이브러리가 부족하면 Docker 배포로 전환합니다.

## 4. 로컬 실행

```bash
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt   # macOS/Linux: .venv/bin/pip
.venv/Scripts/python -m uvicorn backend.app.main:app --reload            # http://localhost:8000/api/health
cd frontend && npm ci && npm run dev                                     # http://localhost:5173 (루트 .env 사용)
```

## 5. OAuth 콘솔 등록값

| 제공자 | 콘솔 | 등록할 Redirect URI (로컬 / 운영) |
|---|---|---|
| Google | Google Cloud Console → API 및 서비스 → 사용자 인증 정보 | `http://localhost:8000/api/auth/oauth/google/callback` / `https://jobpick-api.onrender.com/api/auth/oauth/google/callback` |
| Naver | NAVER Developers → 내 애플리케이션 → API 설정 | `.../api/auth/oauth/naver/callback` (서비스 URL에 프런트 도메인 등록) |
| Kakao | Kakao Developers → 앱 → 카카오 로그인 → Redirect URI | `.../api/auth/oauth/kakao/callback` (플랫폼 → Web 사이트 도메인 등록) |

- 콜백 경로는 백엔드 라우터 확정 시 맞춥니다. 콜백 처리 후에는 `CORS_ORIGINS`에 포함된 프런트 도메인으로만 되돌려 보냅니다.
