# jobpick 배포 환경 설정

## 1. 구성 개요

```plaintext
GitHub (main push)
  └─ GitHub Actions (.github/workflows/deploy.yml, 변경 경로별 실행)
       ├─ frontend/** 변경 ─┬─ Actions에서 빌드 → Netlify CLI 배포 ─→ https://jobpick.netlify.app (데모)
       │                    └─ Render Deploy Hook ─→ Render가 빌드 ─→ https://jobpick.onrender.com
       └─ backend/**, rpa/**, requirements.txt 변경
                            └─ 문법 검사·테스트 통과 후 Render Deploy Hook ─→ https://jobpick-api.onrender.com

브라우저(Netlify·Render 프런트) ──HTTPS + Authorization: Bearer──→ jobpick-api.onrender.com (CORS 허용)
```

- 배포는 **GitHub Actions만** 수행합니다. Netlify의 Git 자동 빌드와 Render의 Auto-Deploy는 끕니다 (이중 배포 방지).
- 두 프런트엔드 모두 `VITE_API_BASE_URL=https://jobpick-api.onrender.com`으로 백엔드를 **직접 호출**합니다.
  - Netlify 프록시(`/api/* → Render`)는 쓰지 않습니다. Netlify 프록시는 26초에 타임아웃되는데, Render 무료 인스턴스는 15분 무요청 시 잠들고 깨어나는 데 약 1분이 걸려 첫 요청이 실패합니다.
  - 토큰은 쿠키가 아닌 `Authorization: Bearer` 헤더로 보내므로 도메인이 달라도 SameSite·서드파티 쿠키 문제가 없습니다.

## 2. GitHub 저장소 설정 (Settings → Secrets and variables → Actions)

| 종류 | 이름 | 값 | 비고 |
|---|---|---|---|
| Secret | `NETLIFY_AUTH_TOKEN` | Netlify → User settings → Applications → Personal access tokens | |
| Secret | `NETLIFY_SITE_ID` | Netlify 사이트 → Site configuration → Project ID | |
| Secret | `RENDER_DEPLOY_HOOK_FRONTEND` | Render `jobpick` Static Site → Settings → Deploy Hook URL | URL 자체가 비밀값 |
| Secret | `RENDER_DEPLOY_HOOK_BACKEND` | Render `jobpick-api` Web Service → Settings → Deploy Hook URL | URL 자체가 비밀값 |
| Variable | `NETLIFY_VITE_API_BASE_URL` | `https://jobpick-api.onrender.com` | 1단계에서는 비워도 됨 |
| Variable | `NETLIFY_VITE_USE_MOCK` | 1단계 `true` → 백엔드 연동 후 `false` | 미설정 시 `true` |

- Netlify 데모는 **Actions에서 빌드**하므로 `VITE_*` 값은 Netlify 대시보드가 아니라 위 GitHub Variables에 등록합니다.
- Mock → 실 API 전환: `NETLIFY_VITE_USE_MOCK=false`로 바꾼 뒤 Actions → Deploy → Run workflow(`frontend`) 실행.
- 시크릿이 비어 있으면 해당 배포 단계는 경고만 남기고 건너뜁니다.

## 3. Netlify (프런트엔드 데모, jobpick.netlify.app)

| 항목 | 값 |
|---|---|
| 사이트 생성 | Add new project → **Deploy manually**(Git 연결 안 함) 또는 `netlify sites:create --name jobpick` |
| 사이트 이름 | `jobpick` |
| Git 연결 시 | Site configuration → Build & deploy → **Stop builds** |
| SPA 라우팅 | 워크플로에서 `dist/_redirects`(`/* /index.html 200`) 자동 생성 |
| 환경 변수 | 대시보드 등록 불필요 (GitHub Variables 사용) |

## 4. Render Static Site (프런트엔드, jobpick.onrender.com)

| 항목 | 값 |
|---|---|
| Name | `jobpick` |
| Repository / Branch | `fsclass-n/jobpick` / `main` |
| Root Directory | `frontend` |
| Build Command | `npm ci && npm run build` |
| Publish Directory | `dist` |
| Auto-Deploy | **Off** (Deploy Hook으로만 배포) |
| Redirects/Rewrites | Source `/*` → Destination `/index.html`, Action **Rewrite** |

| 환경 변수 | 값 |
|---|---|
| `NODE_VERSION` | `24` |
| `VITE_API_BASE_URL` | `https://jobpick-api.onrender.com` |
| `VITE_USE_MOCK` | `false` (2단계 이전에는 `true`) |

## 5. Render Web Service (백엔드 API, jobpick-api.onrender.com)

| 항목 | 값 |
|---|---|
| Name | `jobpick-api` |
| Language / Region | Python 3 / Singapore (TiDB `ap-northeast-1`과 가장 가까운 Render 리전) |
| Root Directory | (비움, 저장소 루트 - `requirements.txt`·`backend`·`rpa` 공용) |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `uvicorn backend.app.main:app --host 0.0.0.0 --port $PORT` (백엔드 구조 확정 후 모듈 경로 맞춤) |
| Health Check Path | `/api/health` (백엔드에 구현) |
| Auto-Deploy | **Off** (Deploy Hook으로만 배포) |
| Python 버전 | 저장소 루트 `.python-version`(`3.11`)으로 고정 (Render 기본값은 3.14) |

| 환경 변수 | 운영 값 / 설정 방법 |
|---|---|
| `APP_ENV` | `production` |
| `DATABASE_URL` | TiDB 접속 문자열 (`mysql+pymysql://...:4000/jobpick?ssl_verify_cert=true&ssl_verify_identity=true`), TLS 오류 시 `&ssl_ca=/etc/ssl/certs/ca-certificates.crt` 추가 |
| `CORS_ORIGINS` | `https://jobpick.netlify.app,https://jobpick.onrender.com` |
| `USER_JWT_SECRET` | `python -c "import secrets; print(secrets.token_urlsafe(64))"` (로컬과 다른 값) |
| `ADMIN_JWT_SECRET` | 위와 같은 방법, `USER_JWT_SECRET`과 다른 값 |
| `USER_JWT_EXPIRE_MINUTES` / `ADMIN_JWT_EXPIRE_MINUTES` | `120` / `30` |
| `ADMIN_LOGIN_MAX_FAILURES` / `ADMIN_LOGIN_LOCK_MINUTES` | `5` / `15` |
| `ADMIN_TOTP_ISSUER` | `jobpick` |
| `ADMIN_TOTP_ENCRYPTION_KEY` | `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` |
| `ADMIN_INITIAL_EMAIL` / `ADMIN_INITIAL_PASSWORD` | **Render에만 등록** (저장소·.env.example 금지) |
| `TEST_USER_*` / `TEST_ADMIN_*` | `.env.example`의 테스트 계정 값 |
| `OAUTH_REDIRECT_BASE_URL` | `https://jobpick-api.onrender.com` |
| `GOOGLE_*` / `NAVER_*` / `KAKAO_*` | 각 개발자 콘솔 값 (아래 6절 콜백 URL 등록 필요) |
| `GEMINI_API_KEY` / `GEMINI_MODEL` | 로컬과 동일 |
| `STORAGE_BACKEND` | `bucket` 권장 (Render 무료 인스턴스 디스크는 재배포·재시작 시 초기화) |
| `DATA_GO_KR_API_KEY` / `SEOUL_OPEN_API_KEY` / `WORK24_API_KEY` / `SARAMIN_ACCESS_KEY` | 발급받은 키 |
| `RPA_HEADLESS` / `RPA_REQUEST_DELAY_SECONDS` / `RPA_SCHEDULE_CRON` / `OCR_LANG` | `true` / `2` / `0 6 * * *` / `kor+eng` |

- Playwright를 Render에서 실행하려면 Build Command에 `&& playwright install chromium`을 추가해야 하며, 네이티브 런타임에서 시스템 라이브러리가 부족하면 Docker 배포로 전환합니다. 공공 API(Requests)만 쓰는 수집은 추가 설정이 없습니다.

## 6. OAuth 콘솔 등록값

| 제공자 | 콘솔 | 등록할 Redirect URI (로컬 / 운영) |
|---|---|---|
| Google | Google Cloud Console → API 및 서비스 → 사용자 인증 정보 | `http://localhost:8000/api/auth/oauth/google/callback` / `https://jobpick-api.onrender.com/api/auth/oauth/google/callback` |
| Naver | NAVER Developers → 내 애플리케이션 → API 설정 | `.../api/auth/oauth/naver/callback` (서비스 URL에 세 프런트 도메인 등록) |
| Kakao | Kakao Developers → 앱 → 카카오 로그인 → Redirect URI | `.../api/auth/oauth/kakao/callback` (플랫폼 → Web 사이트 도메인에 세 프런트 도메인 등록) |

- 콜백 경로는 백엔드 라우터 확정 시 맞춥니다. 콜백 처리 후 백엔드는 로그인을 시작한 프런트 도메인(`CORS_ORIGINS`에 포함된 것만 허용)으로 되돌려 보냅니다.

## 7. 최초 배포 순서

1. Netlify 사이트 생성(Git 미연결) → `NETLIFY_AUTH_TOKEN`, `NETLIFY_SITE_ID` 등록
2. Render Static Site·Web Service 생성 → 환경 변수 입력 → Auto-Deploy Off → Deploy Hook URL 2개를 GitHub Secrets에 등록
3. GitHub Variables 등록 (`NETLIFY_VITE_USE_MOCK=true`)
4. `main`에 push하거나 Actions → Deploy → Run workflow(`all`) 실행
5. 백엔드 연동 완료 후 `NETLIFY_VITE_USE_MOCK=false` → Run workflow(`frontend`)
