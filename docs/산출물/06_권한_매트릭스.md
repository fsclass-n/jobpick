# 06. 권한 매트릭스 및 인증 설계

## 1. 계정 유형

| 구분 | 권한 코드 | 로그인 경로 | 접근 경로 (프런트 / API) | 세션 |
|---|---|---|---|---|
| 일반 사용자 | `USER` | `/login` | 서비스 페이지 / `/api/**` | 사용자 토큰 (`aud=jobpick:user`, 12시간) |
| 테스트 관리자 | `TEST_ADMIN` | `/login` (테스트 관리자 버튼) | `/sandbox/admin/**` / `/api/sandbox/admin/**` | 샌드박스 토큰 (`aud=jobpick:sandbox`, 2시간) |
| 정식 관리자 | `ADMIN` | `/admin/login` (별도 페이지) | `/admin/**` / `/api/admin/**` | 관리자 토큰 (`ADMIN_JWT_SECRET`, `aud=jobpick:admin`, 30분) |

## 2. 기능별 권한

| 기능 | 비로그인 | 일반 사용자 | 테스트 관리자 | 정식 관리자 |
|---|:---:|:---:|:---:|:---:|
| 메인·공고 목록·공고 상세 | O | O | O | O |
| 공고 스크랩 | X | O | O | X ※ |
| 자소서 관리·AI 분석·이력·대시보드 | X | O | O (샌드박스 통계로 기록) | X ※ |
| 관리자 대시보드 | X | X | 샌드박스 데이터 | 운영 데이터 |
| 회원 목록·권한 변경 | X | X | 샌드박스 더미 회원만 | 운영 회원 (USER ↔ TEST_ADMIN) |
| 정식 관리자 권한 부여 | X | X | X | X (서버 스크립트 전용) |
| 수집 대상 관리·수동 실행 | X | X | 샘플(오프라인) 수집기만 | 모든 수집기 |
| 관리자 접속 로그 | X | X | X | O |

※ 정식 관리자 세션은 운영 전용입니다. 관리자 토큰으로 일반 서비스 API를 호출하면 403이 반환됩니다.

## 3. 분리 구현 내역

### 3.1 접근 경로 분리

- 정식 관리자 로그인 페이지는 `/admin/login` 하나뿐입니다. GNB, 일반 로그인 페이지, 푸터에는 링크가 없습니다.
- 일반 로그인 API(`/api/auth/login`)는 `USER`, `TEST_ADMIN` 만 허용합니다.
  - 정식 관리자 계정으로 시도하면 존재 여부를 노출하지 않도록 일반 불일치와 같은 401을 반환합니다.
- 관리자 로그인 API(`/api/admin/auth/login`)는 `ADMIN` 만 허용합니다.
- 테스트 계정 API(`/api/auth/test-accounts`)는 정식 관리자 계정을 절대 포함하지 않습니다.

### 3.2 세션 분리

| 항목 | 일반 / 테스트 관리자 | 정식 관리자 |
|---|---|---|
| 서명 키 | `USER_JWT_SECRET` | `ADMIN_JWT_SECRET` (서로 같으면 관리자 로그인 비활성) |
| 프런트 저장소 | `localStorage.jp_user_session` | `sessionStorage.jp_admin_session` (탭 종료 시 소멸) |
| 만료 | 12시간 / 2시간 | 30분, 만료 시 자동 로그아웃, 남은 시간 표시 |
| 토큰 검증 | `aud`·`iss`·`exp` + DB 권한 재확인 (권한이 바뀌면 403 → 재로그인) | 동일 |

### 3.3 권한 범위 분리

- 관리자 라우터는 `build_admin_router(prefix, guard, sandbox)` 팩토리 하나로 만듭니다. 운영과 샌드박스에 서로 다른 인증 의존성과 `is_sandbox` 필터를 주입합니다.
- 샌드박스 범위의 제한은 다음과 같습니다.
  - 운영 회원·운영 수집 대상의 ID로 요청하면 **404** 입니다.
  - `sample` 외의 수집기는 등록할 수 없습니다 (**403**).
  - 접속 로그 API는 없습니다.
- 테스트 관리자가 실행한 분석은 `is_sandbox=true` 로 저장됩니다. 운영 통계(AI 분석 성공률 등)에 섞이지 않습니다.
- 정식 관리자 계정은 권한·상태를 바꿀 수 없습니다. 본인 계정도 마찬가지입니다.
  - 정식 관리자 생성·비밀번호 재설정은 `python -m backend.scripts.create_admin` 으로만 합니다.

### 3.4 보안 정책

- 비밀번호 규칙: 영문 대문자·소문자·숫자·특수문자를 모두 포함해 8자 이상입니다. 프런트와 백엔드에서 모두 검증합니다.
- 로그인 실패가 `LOGIN_MAX_FAILED`(기본 5)회 쌓이면 `LOGIN_LOCK_MINUTES`(기본 15)분 동안 잠깁니다 (423).
- 정식 관리자 2단계 인증: `ADMIN_TOTP_SECRET` 을 설정하면 TOTP 6자리 코드가 필수가 됩니다.
  - 비밀키는 `create_admin --totp` 로 생성합니다.
- 관리자 접속 로그에 기록하는 항목은 다음과 같습니다.
  - 로그인 성공·실패, 로그아웃
  - 권한 변경, 계정 상태 변경
  - 수집 대상 생성·수정·삭제·실행
  - 테스트 관리자 샌드박스 활동
- 프런트 라우트 가드(`RequireUser`, `RequireSandbox`, `RequireAdmin`)는 UX 용도입니다. 실제 접근 제어는 백엔드 의존성(`get_current_user`, `require_sandbox_admin`, `require_admin`)이 담당합니다.

## 4. 자동 테스트로 검증한 항목 (`backend/tests/test_auth.py`, `test_admin.py`)

- 정식 관리자는 일반 로그인 경로로 로그인할 수 없습니다. 반대로 일반·테스트 계정은 관리자 경로로 로그인할 수 없습니다.
- 토큰 종류별로 정상 경로와 금지 경로 9가지를 점검했습니다. 예를 들어 사용자 → 관리자 API는 403, 관리자 → 서비스 API는 403입니다.
- 테스트 계정 API에 정식 관리자 계정이 포함되지 않습니다.
- 로그인 5회 실패 후 계정이 잠깁니다.
- 샌드박스와 운영의 회원·수집 대상이 섞이지 않습니다.
- 권한 변경 규칙이 지켜지고, 변경 내역이 로그에 남습니다.
