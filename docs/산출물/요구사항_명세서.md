# jobpick 요구사항 명세서 (v2 · Pick 여정 개편)

> 공고를 고르는 서비스가 아니라, **합격까지의 거리를 줄여 주는** 생성형 AI & RPA 커리어 코치

## 1. 서비스 콘셉트

### 1-1. 기존 서비스와의 차이
기존 취업 서비스는 대부분 "공고 목록 + 자소서 첨삭" 중 한 가지만 제공합니다. jobpick은 RPA가 수집한 공고 데이터를 한 번 정형화한 뒤 **네 단계를 하나의 여정(Pick 여정)으로 연결**하고, 단계마다 쌓인 결과를 **Pick Score** 하나로 보여 줍니다.

| 단계 | 이름 | 기존 서비스 | jobpick |
|---|---|---|---|
| 1 | **Match** (Pick 레이더) | 키워드·조건 검색 | 내 프로필·자소서와 공고를 대조해 공고별 적합도와 **합격 거리(Gap Distance)** 산출 |
| 2 | **Gap** (갭 로드맵) | 공고 1건 단위 분석 | 관심 공고 N개의 요구역량을 집계해 **"시장이 요구하는데 나에게 없는 역량 TOP"**과 주차별 보완 계획 제시 |
| 3 | **Rewrite** (리라이팅 스튜디오) | 문서형 첨삭 리포트 | 문항별 원문 vs AI 제안 **diff 편집기**, 공고 키워드 하이라이트, 수정할 때마다 적합도 실시간 변동 |
| 4 | **Rehearse** (모의면접) | 별도 서비스 | 자소서의 약점·공고 인재상에서 **압박·꼬리 질문**을 생성하고 답변을 채점 |

### 1-2. Pick Score
세 가지 점수를 합산한 0~100점 지표입니다. 모든 화면 상단에 노출되어 "지금 내가 합격선에서 얼마나 떨어져 있는지"를 보여 줍니다.

| 구성 | 비중 | 산출 근거 |
|---|---|---|
| 서류 적합도 (Match) | 50% | 자격요건 충족도, 우대사항 일치율, 인재상 키워드 일치율 |
| 역량 커버리지 (Gap) | 30% | 관심 공고 N개 요구역량 중 내가 보유한 비율(공고 노출 빈도 가중) |
| 면접 준비도 (Rehearse) | 20% | 모의면접 답변의 구체성·직무 연관성·일관성 평가 |

- **합격 거리(Gap Distance)** = 목표 공고의 합격선 기준점수 − 내 Pick Score
- 합격선 기준점수는 공고 정형화 결과(요구 수준)에 따라 산정하며, 실제 합격을 보장하지 않는 **참고 지표**임을 화면에 명시합니다.

## 3. 기술 스택

### Frontend
- React (Vite), React Router (공통 Layout, 권한별 라우트 가드), Tailwind CSS v4
- 시각화: 직접 구현한 SVG/CSS 차트(레이더·갭 막대·추이선) — 외부 차트 라이브러리 미사용으로 번들 경량화

### Backend & API
- Python 3.11.x, FastAPI
- 인증: JWT(권한별 비밀키 분리), bcrypt, OAuth 2.0(Google·Naver·Kakao), 관리자 TOTP
- 환경 변수: `.env` (python-dotenv)

### Database & Storage
- TiDB Cloud(MySQL 호환, 로컬 SQLite 가능), 로컬/클라우드 버킷(자소서 원본, 공고 원문, 리포트)

### Cloud / CI·CD
- Netlify(데모), Render(프런트·API), Docker/Docker Compose
- GitHub Actions는 CI 게이트, 배포는 Netlify·Render의 GitHub 연동 (`netlify.toml`, `render.yaml`, GitHub Secrets 미사용)

### Data / RPA / External
- Requests, BeautifulSoup4, Playwright, OCR(PDF·이미지 → 텍스트), NumPy, pandas(역량 집계)
- 수집원(우선순위): ① 공공데이터포털(나라일터·ALIO·지방공공기관) ② 서울 열린데이터광장 ③ 고용24(개인 신청: 공채속보 등) ④ 사람인(승인제)
- 고용24 채용정보 목록/상세 API는 개인 신청 불가이므로 주 수집원에서 제외
- 크롤링은 robots.txt·이용약관을 확인한 사이트에 한해 저빈도로 수행

### AI (Google Gemini)
| 기능 | 입력 | 출력 |
|---|---|---|
| 공고 정형화 | 공고 원문 | 직무, 자격요건, 우대사항, 인재상, 요구역량 태그(표준 사전 기준) |
| 매칭 분석 | 정형 공고 + 프로필·자소서 | 서류 적합도, 항목별 충족/미충족 |
| 갭 분석 | 관심 공고 N개 정형 데이터 + 내 역량 | 부족 역량 순위, 주차별 보완 계획 |
| 리라이팅 | 문항 원문 + 공고 | 수정 제안문, 변경 이유, 반영 키워드 |
| 모의면접 | 자소서 + 공고 | 질문(기본·압박·꼬리), 답변 평가 |

- 출력은 JSON 스키마로 강제하고 검증 실패 시 재시도합니다.
- 사용자 자소서 원문은 분석 요청에만 사용하며 학습 용도로 쓰지 않는다는 점을 개인정보 처리방침에 명시합니다.

## 5. 단계별 개발 프로세스
1. **1단계 (프런트 + Netlify 데모)**: Mock 데이터·Mock 인증으로 Pick 여정 전체 화면 구성
2. **2단계 (백엔드·RPA·AI 통합)**: 인증, 공고 수집·정형화, Match/Gap/Rewrite/Rehearse API, TiDB 연동 로컬 검증
3. **3단계 (Render 배포)**: 프런트·API 운영 배포, Netlify 데모를 실 API로 전환

## 6. 개발 환경 규칙
- 환경 변수는 루트 `.env` 하나로 관리하고 `.env.example`에 Frontend/Backend/RPA를 구분 (Vite는 `envDir: '..'`)
- `.venv` + 단일 `requirements.txt`
- 프런트 API 주소는 `VITE_API_BASE_URL`, 백엔드 CORS는 `CORS_ORIGINS`
- 배포 트리거: `frontend/**` → Netlify + Render 프런트, `backend/**`·`rpa/**`·`requirements.txt`·`.python-version` → Render API
- 비밀값: `USER_JWT_SECRET`과 `ADMIN_JWT_SECRET`은 서로 다른 값, `ADMIN_INITIAL_*`와 TOTP 시크릿은 Render에만 등록하고 저장소·`.env.example`·프런트에 넣지 않음

## 7. 산출물 규칙 (docs)
- `md/` 작업 기록 누적, `프로젝트_진행일지/` 일정·팀원별 업무, `산출물/` 설계서, `pdf/` PDF 변환본, `프로젝트_발표자료.pptx`

## 8. UI/UX 디자인 원칙

### 8-0. 비주얼 아이덴티티 (v3 · 2026-11-23)
- **핵심 인터랙션 — 오늘의 덱**: 메인 히어로에서 RPA가 수집한 공고를 카드 덱으로 제공. 오른쪽(✓/→)은 Pick, 왼쪽(✕/←)은 패스, 되돌리기 지원. Pick할 때마다 역량 커버리지·Pick Score가 즉시 갱신되고, 덱을 끝내면 갭 분석으로 이어짐
- **색**: 네이비 #0f1033(양복) · 코랄 #ff5a3c(넥타이·강조) · 민트 #19d3a2(Pick·보유) · 배경 #f5f5fa
- **타이포 2종**: 본문·제목 Pretendard, 숫자·영문 Space Grotesk
- **레이아웃**: 라운드 28px 벤토 그리드 타일, 실사 사진 타일, 플로팅 글래스 헤더(단일 CTA), 라운드 네이비 푸터 + 원형 코랄 To the Top
- **로고·파비콘**: 양복 칼라 + 넥타이 + 라펠 핀 체크(✓) = "합격해 넥타이를 매는 순간을 Pick"
- **사진**: Unsplash 무료 라이선스(상업 이용 가능, 출처 표기 권장) 이미지를 저장소에 내려받아 사용하고 푸터에 작가 크레딧 표기

### 8-1. 독창성 (Pick 모티프)
- **히어로 인터랙션**: 화면 양쪽에서 공고 카드와 자소서 카드가 다가와 겹치면 일치 키워드가 선으로 연결되고 Pick Score가 0에서 올라가며, 마지막에 체크 마크(Pick)가 찍힘
- **Pick 여정 트래커**: 모든 서비스 화면 상단에 Match → Gap → Rewrite → Rehearse 진행 상태와 Pick Score, 합격 거리 표시
- 브랜드 요소: 적합도 게이지, 키워드 하이라이트, 체크 마크를 로고·로딩·리포트에 일관 적용
- 스크롤 진입·카드 호버 등 마이크로 인터랙션 적용, `prefers-reduced-motion` 사용자는 애니메이션 최소화

### 8-2. 공통 레이아웃
- 모든 페이지에 전역 Header/Footer를 React Router Layout으로 적용
- **헤더**: 로고, GNB(공고 매칭 / 갭 로드맵 / 리라이팅 / 모의면접 / 내 여정), 로그인 상태별 사용자 메뉴·권한 배지, 스크롤 시 높이 축소 + 반투명 블러
- **모바일**: 햄버거 ↔ X 전환 모션, 우측에서 열리는 드로어(사용자 정보·권한 배지 포함)
- **푸터**: 서비스 소개, 이용약관·개인정보처리방침, 팀 정보(박미금·이오리·김모란·홍기흥), GitHub 링크, 저작권, 부드럽게 올라가는 To the Top 버튼
- 관리자 페이지는 전역 헤더·푸터를 유지하고 본문에 전용 사이드바 추가
- 타이포그래피 웹폰트 2종(제목/본문), 아이콘 일관 적용, 모바일·태블릿·데스크톱 반응형

## 9. 권한 및 로그인

| 구분 | 권한 코드 | 진입 경로 | 관리자 화면 | 데이터 변경 | 세션 |
|---|---|---|---|---|---|
| 일반 사용자 | `USER` | `/login` (체험하기·이메일·소셜) | 접근 불가 | 본인 데이터만 | 사용자 토큰 |
| 테스트 관리자 | `TEST_ADMIN` | `/login`의 "테스트 관리자" 버튼 | 전체 메뉴·뷰 노출 | **읽기 전용** (생성·수정·삭제 버튼 비활성 + 서버 403) | 사용자 비밀키로 서명한 테스트 관리자 토큰 |
| 실제 관리자 | `ADMIN` | `/admin/login` (링크 비노출) | 전체 | **전체 CRUD** | `ADMIN_JWT_SECRET` 서명, 30분 만료 |

- **실제 관리자**: 서버 환경 변수 `ADMIN_ACCESS_KEY`와 일치하는 관리자 키를 입력해야 진입합니다. 키는 로컬 `.env`·Render 대시보드에만 등록하고 저장소·프런트 코드에 넣지 않습니다. 5회 실패 시 15분 잠금(429).
- **테스트 관리자**: QA·시연용. 화면 구성은 실제 관리자와 같고, `/api/admin/**`에 GET 외 요청을 보내면 서버가 403으로 차단합니다(프런트 가드만으로 막지 않음). 헤더 상단에 "TEST ADMIN — 읽기 전용 모드" 경고 띠를 고정 표시합니다.
- 토큰 저장 키 분리: `jobpick.user.token` / `jobpick.testadmin.token` / `jobpick.admin.token` (sessionStorage)
- 비밀번호 규칙: 영문 대소문자·숫자·특수문자 조합 8자 이상(입력 중 실시간 검증)
- 권한이 없으면 각 권한의 로그인 페이지 또는 403 안내로 이동하며, 알 수 없는 경로는 메인(`/`)으로 이동합니다. 최초 접속은 항상 메인 페이지입니다.

- AI 결과는 "참고용"임을 명시하고, 사용자 데이터는 본인만 조회·삭제 가능
