# jobpick 요구사항 명세서

> 생성형 AI & RPA 기반 맞춤형 커리어 컨설팅 시스템

## 📌 서비스 콘셉트
- **개요**: RPA가 채용 플랫폼과 공공 채용정보 API에서 채용 공고를 자동으로 수집합니다. 생성형 AI(LLM)는 수집된 공고의 자격요건, 우대사항, 인재상을 사용자의 자기소개서·이력서와 비교합니다. 그 결과로 **합격 가능성(적합도)을 분석**하고 **문항별 수정 가이드라인**을 작성해 주는 맞춤형 커리어 컨설팅 솔루션입니다.
- **프로젝트명**: jobpick
- **팀 구성**: 4인 팀 프로젝트
  - 박미금 (조장)
  - 이오리
  - 김모란
  - 홍기흥

## 🛠️ 기술 스택 (Tech Stack)

### 1. Frontend
- **Core**: HTML5, CSS3, React (Vite), React Router (공통 레이아웃 및 권한별 라우트 가드)
- **Styling**: Tailwind CSS v4, Flexbox

### 2. Backend & API
- **Language & Framework**: Python 3.11.x, FastAPI
- **Authentication**: JWT 기반 인증 (권한별 토큰 분리), 비밀번호 해시(bcrypt), OAuth 2.0 (Google, Naver, Kakao), TOTP 2단계 인증 (정식 관리자)
- **Environment Management**: .env (python-dotenv)

### 3. Database & Storage
- **RDBMS**: TiDB 클라우드 DB (또는 MySQL / SQLite 연동)
- **Object Storage**: 로컬 스토리지 및 클라우드 버킷 (자소서·이력서 원본 파일, 수집 공고 원문, AI 분석 리포트 관리)

### 4. Cloud / Infrastructure & CI/CD
- **Cloud Platform**: Render (PaaS 프런트엔드·백엔드), Netlify (프런트엔드 데모)
- **Containerization**: Docker, Docker Compose
- **CI/CD Pipeline**: GitHub Actions CI(.github/workflows/deploy.yml) + Netlify·Render GitHub 연동 자동 배포 (`netlify.toml`, `render.yaml`)

### 5. Data Analysis, RPA & External Services
- **Data Processing**: NumPy, pandas (공고 키워드 빈도 분석, 직무별 요구역량 통계)
- **Web Crawling, OCR & RPA**: Requests, BeautifulSoup4, Playwright (채용 공고 자동 수집), OCR 엔진 (PDF·이미지 형식의 자소서/이력서 텍스트 추출)
- **External APIs** (채용 공고 수집원, 우선순위 순)
  1. 공공데이터포털(자동승인): 인사혁신처_공공취업정보(나라일터), 재정경제부_공공기관 채용정보(ALIO), 행정안전부 한국지역정보개발원_채용정보(지방공공기관)
  2. 서울 열린데이터광장: 서울시 일자리플러스센터 채용정보(`GetJobInfo`, 민간 기업 공고)
  3. 고용24 Open API (개인 신청): 공채속보·채용행사·공채기업정보 (채용정보 목록/상세 API는 개인 이용 불가)
  4. 사람인 채용정보 API (승인제, 일 500회, 출처 표기 필수) - 승인 시 추가 연동
  - 민간 채용 플랫폼 크롤링(Playwright)은 robots.txt·이용약관을 확인한 사이트에 한해 소량·저빈도로 수행

### 6. AI Integration
- **LLM & Generative AI**: Google Gemini API
  - 채용 공고 정형화 (직무, 자격요건, 우대사항, 인재상 추출)
  - 자소서-공고 대조 분석 및 합격 가능성(적합도) 점수 산출
  - 문항별 강점·약점 진단 및 수정 가이드라인 생성

## 🚀 단계별 개발 및 배포 프로세스
- **작업 1단계 (프런트엔드 개발 및 Netlify 데모 배포)**: React 기반 UI 개발, 목(Mock) 데이터와 Mock 인증으로 화면을 구성해 Netlify(jobpick.netlify.app)에 정적 데모 배포
- **작업 2단계 (백엔드·RPA·AI 통합 및 로컬 검증)**: FastAPI, 권한별 인증 시스템, 채용 공고 수집 RPA, OCR/LLM 자소서 분석, TiDB 연동 로컬 테스트
- **작업 3단계 (Render를 활용한 프런트엔드·백엔드 배포)**: Render 환경에 프런트엔드(jobpick.onrender.com)와 프로덕션 API 서버(jobpick-api.onrender.com) 구축 완료

## ⚙️ 개발 환경 규칙
- 환경 변수는 .env 파일 하나로 관리 (Render는 대시보드 설정에 직접 등록, .env.example에 프런트/백엔드/RPA 구분 표시)
- 파이썬 가상환경 디렉터리는 .venv 사용 및 단일 requirements.txt로 라이브러리 통합 관리
- Netlify(프런트 데모), Render 프런트엔드, Render 백엔드는 각 서비스 영역 파일이 변경될 때만 개별 자동 배포 수행
  - `frontend/**` 변경 → Netlify 데모 + Render 프런트엔드 배포
  - `backend/**`, `rpa/**`, `requirements.txt` 변경 → Render 백엔드 API 배포
- 프런트엔드의 API 주소는 환경 변수(`VITE_API_BASE_URL`)로 분리하고, 백엔드 CORS에 세 배포 도메인 모두 허용
- **인증 관련 비밀값 관리**
  - 일반/테스트용 JWT 비밀키(`USER_JWT_SECRET`)와 정식 관리자 JWT 비밀키(`ADMIN_JWT_SECRET`)는 서로 다른 값 사용
  - 정식 관리자 초기 계정 정보(`ADMIN_INITIAL_EMAIL`, `ADMIN_INITIAL_PASSWORD`)는 Render 대시보드에만 등록하고, 저장소·.env.example·프런트엔드 코드에는 값을 넣지 않음
  - 정식 관리자 TOTP 시크릿은 계정별로 서버에서 생성해 DB에 암호화 저장하며, 저장소·.env.example에는 값을 넣지 않음
  - 테스트 계정(일반 사용자, 테스트 관리자) 정보만 .env.example에 예시값으로 기재 가능

## 🎨 UI/UX 디자인 원칙

### 1. 독창성 확보
- 서비스 정체성인 **"공고와 나를 맞대어 딱 맞는 기회를 고른다(Pick)"**를 직관적으로 드러내는 비주얼 컨셉과 인터랙션 적용
- **메인 히어로 인터랙션 예시**: 채용 공고 카드와 자소서 카드가 화면 양쪽에서 다가와 겹치면, 서로 일치하는 키워드끼리 선으로 연결되고 적합도 점수가 0%부터 올라가는 카운트업 애니메이션
- **브랜드 요소**: 적합도 게이지, 키워드 하이라이트, 체크 마크(Pick) 모티프를 로고·아이콘·로딩 화면·분석 리포트에 일관되게 사용
- 스크롤 진입 애니메이션, 카드 호버 효과 등 마이크로 인터랙션을 적용하되 `prefers-reduced-motion` 설정 사용자는 애니메이션 최소화

### 2. 공통 레이아웃 (전역 헤더·푸터)
- 메인을 포함한 **모든 하위 페이지**에 상용 수준의 완성도를 갖춘 전역 헤더(Header)와 푸터(Footer)를 고정 배치 (React Router 공통 Layout 컴포넌트로 일괄 적용)
- **헤더**
  - 로고, GNB(채용 공고 / 자소서 관리 / AI 분석 / 분석 이력), 로그인 상태별 사용자 메뉴
  - 스크롤하면 높이가 줄고 배경이 반투명 블러 처리되는 Sticky 헤더
  - 로그인 권한 배지 표시 (일반 사용자 / 테스트 관리자 / 관리자)
  - 테스트 관리자로 로그인하면 헤더 상단에 **"SANDBOX 모드"** 경고 띠를 고정 표시해 정식 환경과 시각적으로 구분
- **푸터**
  - 서비스 소개, 이용약관·개인정보처리방침 링크, 팀 정보(박미금·이오리·김모란·홍기흥), GitHub 링크, 저작권 표기
  - 부드러운 스크롤 애니메이션이 적용된 'To the Top' 버튼
- 관리자 페이지는 전역 헤더·푸터를 유지하고, 본문 영역에 관리자 전용 사이드바를 추가

## 🔐 권한별 로그인 시스템 (테스트 및 정식 계정 분리)
로그인 시스템은 권한과 목적에 따라 아래 3가지 유형으로 명확히 구분하여 구현합니다.

| 구분 | 권한 코드 | 로그인 경로 | 접근 경로 (프런트 / API) | 세션 |
|---|---|---|---|---|
| 일반 사용자 | `USER` | `/login` | 서비스 페이지 / `/api/**` | 사용자 토큰 |
| 테스트 관리자 | `TEST_ADMIN` | `/login` (테스트 관리자 버튼) | `/sandbox/admin/**` / `/api/sandbox/admin/**` | 샌드박스 토큰 |
| 정식 관리자 | `ADMIN` | `/admin/login` (별도 페이지) | `/admin/**` / `/api/admin/**` | 관리자 토큰 (TOTP 필수) |

### 1. 일반 사용자 로그인
- 일반 서비스(공고 탐색, 자소서 관리, AI 분석, 분석 이력) 이용 권한을 가진 사용자 계정
- 이메일 회원가입·로그인과 소셜 로그인(Google, Naver, Kakao) 지원
- 테스트용 일반 사용자 계정 간편 로그인 버튼 제공

### 2. 테스트 관리자 로그인
- 개발 및 QA 단계에서 사용하는 테스트용 관리자 계정
- 정식 관리자 기능 검증을 위한 **샌드박스 환경**에만 접근 허용
  - 관리자 화면과 기능은 정식 관리자와 동일하게 구성하되, 더미 회원·더미 공고 등 샌드박스 데이터만 조회·수정
  - 실제 회원 개인정보, 실서비스 데이터, 운영 설정(RPA 실수집 스케줄, API 키 등)에는 접근 불가
- 로그인 페이지의 테스트 관리자 간편 로그인 버튼으로 접속

### 3. 정식 관리자 로그인
- 실서비스 운영 및 최고 관리 권한을 가진 정식 계정
- 테스트 관리자 계정과 **세션, 권한 범위, 접근 경로를 완전히 분리**
  - **접근 경로**: 별도 로그인 페이지(`/admin/login`) 사용, GNB와 일반 로그인 페이지에는 링크를 노출하지 않음
  - **세션**: 별도 JWT 비밀키(`ADMIN_JWT_SECRET`)로 서명한 관리자 전용 토큰 발급, 일반/샌드박스 토큰과 저장 키 분리, 짧은 만료 시간(예: 30분) 적용
  - **권한 범위**: `/api/admin/**`는 정식 관리자 토큰만 허용하고, 테스트 관리자 토큰으로 요청하면 403 반환
- 간편 로그인 버튼 미제공, 회원가입 경로로 생성 불가 (서버 초기화 스크립트로만 생성)
- 로그인 실패 횟수 제한(예: 5회 실패 시 일정 시간 잠금) 및 관리자 접속 로그 기록
- **2단계 인증(TOTP) 필수**
  - 이메일·비밀번호 검증 후 TOTP 코드(Google Authenticator 등 인증 앱의 6자리 코드)까지 통과해야 관리자 토큰 발급
  - TOTP 미등록 계정은 최초 로그인 시 QR 코드로 등록을 완료해야 관리자 기능 사용 가능
  - TOTP 코드 실패도 로그인 실패 횟수에 포함하고, 등록·해제·재설정 이력을 관리자 접속 로그에 기록
  - 인증 앱 분실 시 복구는 서버 스크립트로만 TOTP 재설정 (관리자 화면에서 자체 해제 불가)

### 공통 인증 규칙
- 비밀번호 유효성 검사: 영문 대소문자, 숫자, 특수문자를 조합한 8자리 이상
- 프런트엔드 라우트 가드와 백엔드 API 권한 검사를 모두 적용 (프런트 가드만으로 접근 제어하지 않음)
- 권한이 없는 경로에 접근하면 각 권한에 맞는 로그인 페이지 또는 403 안내 페이지로 이동
- 1단계 Netlify 데모에서는 Mock 인증으로 3종 로그인 화면 흐름(TOTP 입력 화면 포함)만 확인하고, 실제 정식 관리자 인증은 백엔드 연동(2단계) 이후 활성화

## 💻 페이지별 기능 및 UI/UX 개선 요구사항

### 1. 메인 페이지
- 위 "독창성 확보" 원칙에 따른 히어로 섹션 (공고-자소서 매칭 인터랙션, 적합도 카운트업)
- 서비스 이용 흐름 소개 (공고 수집 → 자소서 등록 → AI 분석 → 수정 가이드)
- 최근 수집 공고 미리보기, 직무별 인기 키워드, 분석 리포트 샘플 화면
- 로그인 상태에 따라 CTA 버튼 변경 (비로그인: "무료로 분석 시작하기", 로그인: "내 대시보드로 이동")

### 2. 로그인 페이지 (일반 사용자 / 테스트 관리자)
- **레이아웃 구조**: Split 화면 구성 (좌측: 맞춤형 커리어 컨설팅 브랜드 그래픽, 우측: 로그인 폼)
- **테스트 계정 간편 로그인**: 일반 사용자(구직자) / 테스트 관리자 계정 버튼 (클릭 시 자동 입력 및 로그인)
- **소셜 로그인 (OAuth)**: 구글(Google), 네이버(Naver), 카카오(Kakao) 로그인 버튼 추가
- **비밀번호 유효성 검사**: 입력 중 실시간으로 조건 충족 여부 표시

### 3. 정식 관리자 로그인 페이지 (`/admin/login`)
- 일반 로그인 페이지와 구분되는 관리자 전용 디자인 (어두운 톤, 관리자 전용 표시)
- 1단계: 이메일·비밀번호 입력 → 2단계: TOTP 6자리 코드 입력 (미등록 시 QR 등록 화면)
- 간편 로그인·소셜 로그인·회원가입 링크 없음

### 4. 모바일 헤더 & 내비게이션 (GNB)
- **햄버거 메뉴 애니메이션**: 클릭하면 햄버거 아이콘과 X자형 아이콘이 서로 전환되는 모션
- **슬라이딩 뷰**: 상용 모바일 플랫폼처럼 우측에서 좌측으로 열리는 드로어(Drawer) 슬라이드 애니메이션
- 드로어 안에 로그인 사용자 정보와 권한 배지 표시

### 5. 핵심 서비스 페이지
- **채용 공고 탐색**: RPA가 수집한 공고 목록 조회, 직무·지역·경력·기업 규모 필터 및 검색, 관심 공고 스크랩
- **자소서·이력서 관리**: 텍스트 직접 입력 또는 PDF·이미지 업로드(OCR 추출), 문항별 버전 관리
- **AI 분석 리포트**: 선택한 공고와 자소서를 대조해 합격 가능성(적합도) 점수, 키워드 매칭률, 강점·보완점, 문항별 수정 가이드라인 및 개선 예시 문장 제공
- **분석 이력**: 과거 분석 결과 비교 및 점수 변화 추이 시각화

### 6. 전반적인 페이지 디자인 및 레이아웃
- **레이아웃 개편**: 메인 대시보드와 공통 요소를 상용 커리어 플랫폼(SaaS) 스타일로 리뉴얼
- **타이포그래피 & 아이콘**: 웹 폰트 2종 이원화(제목용/본문용) 및 FontAwesome 아이콘 일관 적용
- **반응형**: 모바일·태블릿·데스크톱 전 구간 대응

### 7. 관리자(Admin) 페이지
정식 관리자(`/admin/**`)와 테스트 관리자(`/sandbox/admin/**`)는 같은 화면 구성을 쓰고, 대상 데이터와 권한만 다르게 동작합니다.

- **회원 관리**: 사용자 목록 조회 및 회원 권한 변경
  - 정식 관리자: 실제 회원 대상 권한 변경 (일반 사용자 ↔ 테스트 관리자). 정식 관리자 권한 부여는 서버 스크립트로만 가능
  - 테스트 관리자: 샌드박스 더미 회원 대상으로만 권한 변경 테스트 가능
- **모니터링 대시보드**: RPA 채용 공고 수집 현황(일별 수집 건수, 출처별 성공/실패), AI 자소서 분석 성공률 및 처리 건수 통계 시각화 (테스트 관리자는 샌드박스 통계만 표시)
- **수집 관리**: 크롤링 대상 사이트·키워드 설정 및 수집 작업 수동 실행/스케줄 관리 (실수집 스케줄 변경은 정식 관리자만 가능)
- **관리자 접속 로그**: 정식 관리자 로그인 이력(TOTP 인증 결과 포함) 및 주요 변경 작업 기록 조회 (정식 관리자 전용)
