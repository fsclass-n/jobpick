# 01. 요구사항 정의서

| 항목 | 내용 |
|---|---|
| 프로젝트명 | jobpick — 생성형 AI & RPA 기반 맞춤형 커리어 컨설팅 시스템 |
| 팀 | 박미금(조장), 이오리, 김모란, 홍기흥 |
| 문서 버전 | v1.0 (2026-11-18) |

## 1. 서비스 개요

RPA가 공공 채용정보 API와 채용 게시판에서 채용 공고를 자동으로 수집합니다. 생성형 AI(Google Gemini)는 공고의 **자격요건·우대사항·인재상**을 사용자의 자기소개서와 대조해 **합격 가능성(적합도)** 을 점수로 보여 줍니다. 아울러 **문항별 수정 가이드라인**과 개선 예시 문장을 제공합니다.

## 2. 사용자 및 권한

| 구분 | 권한 코드 | 설명 |
|---|---|---|
| 일반 사용자 | `USER` | 공고 탐색, 자소서 관리, AI 분석, 분석 이력 이용 |
| 테스트 관리자 | `TEST_ADMIN` | 개발/QA용. 정식 관리자 기능을 **샌드박스 데이터**로만 검증 |
| 정식 관리자 | `ADMIN` | 실서비스 운영 및 최고 관리 권한. 세션·권한 범위·접근 경로가 완전히 분리됨 |

## 3. 기능 요구사항

### 3.1 인증 (FR-AUTH)

| ID | 요구사항 | 우선순위 | 구현 |
|---|---|---|---|
| FR-AUTH-01 | 로그인 페이지는 Split 레이아웃(좌: 브랜드 그래픽, 우: 폼)으로 구성 | 상 | `pages/Login.jsx`, `components/AuthSplit.jsx` |
| FR-AUTH-02 | 테스트 계정(일반 사용자/테스트 관리자) 간편 로그인 버튼 — 자동 입력 후 로그인 | 상 | `GET /api/auth/test-accounts` |
| FR-AUTH-03 | 소셜 로그인(Google, Naver, Kakao) OAuth 2.0 | 상 | `routers/oauth.py` |
| FR-AUTH-04 | 비밀번호: 영문 대·소문자, 숫자, 특수문자 조합 8자 이상, 입력 중 실시간 조건 표시 | 상 | `security.py`, `lib/password.js` |
| FR-AUTH-05 | 정식 관리자는 별도 경로(`/admin/login`)에서만 로그인, GNB·일반 로그인 페이지에 링크 미노출 | 상 | `pages/AdminLogin.jsx` |
| FR-AUTH-06 | 정식 관리자 토큰은 별도 비밀키로 서명, 짧은 만료(30분), 세션 저장소 분리 | 상 | `ADMIN_JWT_SECRET`, `sessionStorage` |
| FR-AUTH-07 | 로그인 5회 실패 시 일정 시간 계정 잠금 | 중 | `services/auth_service.py` |
| FR-AUTH-08 | 정식 관리자 2단계 인증(TOTP) — 환경 변수 설정 시 활성화 (권장 사항) | 하 | `ADMIN_TOTP_SECRET` |

### 3.2 채용 공고 (FR-JOB)

| ID | 요구사항 | 구현 |
|---|---|---|
| FR-JOB-01 | RPA 수집 공고 목록 조회, 직무·지역·경력·기업 규모 필터, 검색, 정렬 | `GET /api/jobs` |
| FR-JOB-02 | 공고 상세(소개·자격요건·우대사항·인재상·키워드) | `GET /api/jobs/{id}` |
| FR-JOB-03 | 관심 공고 스크랩/해제 | `POST/DELETE /api/jobs/{id}/scrap` |
| FR-JOB-04 | 인기 키워드 집계(직무별) | `GET /api/jobs/keywords/popular` |

### 3.3 자소서·이력서 (FR-RES)

| ID | 요구사항 | 구현 |
|---|---|---|
| FR-RES-01 | 문항별 텍스트 직접 입력 | `ResumeEditor.jsx` |
| FR-RES-02 | PDF·이미지·TXT 업로드 → OCR 추출 → 문항 자동 분리 | `POST /api/resumes/ocr`, `rpa/ocr.py` |
| FR-RES-03 | 수정 시마다 버전 자동 증가, 버전 이력 조회·복원 | `PUT /api/resumes/{id}`, `restore` |

### 3.4 AI 분석 (FR-AI)

| ID | 요구사항 | 구현 |
|---|---|---|
| FR-AI-01 | 공고와 자소서를 대조해 적합도 점수(0~100)와 등급 산출 | `services/analyzer.py` |
| FR-AI-02 | 키워드 매칭률, 자격요건·우대사항·인재상 충족도, 문장 완성도(STAR·정량 성과) | 동일 |
| FR-AI-03 | 강점·보완점, 문항별 수정 가이드라인과 개선 예시 문장, 다음 행동 | 동일 |
| FR-AI-04 | Gemini 장애 시 규칙 기반 엔진 결과로 대체(폴백)하고 상태 기록 | `status=fallback` |
| FR-AI-05 | 분석 이력, 점수 추이 그래프, 두 결과 비교 | `History.jsx` |

### 3.5 관리자 (FR-ADM)

| ID | 요구사항 | 구현 |
|---|---|---|
| FR-ADM-01 | 회원 목록 조회 및 권한 변경(일반 사용자 ↔ 테스트 관리자). 정식 관리자 권한은 서버 스크립트로만 부여 | `PATCH /users/{id}/role` |
| FR-ADM-02 | 모니터링: RPA 수집 현황(일별, 출처별 성공/실패), AI 분석 성공률·처리 건수 시각화 | `GET /stats` |
| FR-ADM-03 | 수집 관리: 대상 사이트·키워드·스케줄 설정, 수동 실행, 실행 이력 | `/crawl/**` |
| FR-ADM-04 | 관리자 접속 로그(정식 관리자 전용) | `GET /api/admin/logs` |
| FR-ADM-05 | 테스트 관리자는 동일 화면을 `/sandbox/admin` 에서 샌드박스 데이터로만 사용 | `build_admin_router(sandbox=True)` |

## 5. 비기능 요구사항

| 구분 | 내용 |
|---|---|
| 보안 | bcrypt 해시, 권한별 JWT 분리, 백엔드 권한 검사(프런트 가드만으로 접근 제어하지 않음), 비밀값은 저장소에 커밋 금지 |
| 수집 윤리 | robots.txt 준수, 요청 간 지연(`CRAWL_DELAY_SECONDS`), 사용자 에이전트 명시 |
| 가용성 | Gemini 장애 시 규칙 기반 폴백, Render 무료 플랜 콜드스타트 안내 메시지 |
| 이식성 | SQLite(로컬) / MySQL·TiDB(운영)를 `DATABASE_URL` 로 전환 |
| 배포 | 영역별 변경 시에만 개별 자동 배포 (GitHub Actions paths-filter) |
