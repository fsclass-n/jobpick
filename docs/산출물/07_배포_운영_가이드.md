# 07. 배포·운영 가이드

## 1. 배포 환경

| 구분 | URL | 플랫폼 | 배포 방식 |
|---|---|---|---|
| 프런트엔드 데모 | https://jobpick.netlify.app | Netlify | Mock 모드 정적 빌드 (`npm run build:demo`) |
| 프런트엔드 | https://jobpick.onrender.com | Render Static Site | API 연동 빌드 (`VITE_API_BASE_URL`) |
| 백엔드 API | https://jobpick-api.onrender.com | Render Web Service | `uvicorn backend.app.main:app` |
| 프로젝트 안내 | https://fsclass-n.github.io/jobpick/ | GitHub Pages | `docs/site` |

## 2. 단계별 배포 절차

### 1단계 — 프런트엔드 + Netlify 데모 배포

1. Netlify 에서 **Add new site → Import from Git** 으로 저장소를 연결하고, 사이트 이름을 `jobpick` 으로 정합니다.
   - 빌드 설정은 `netlify.toml` 이 자동으로 적용됩니다 (base=`frontend`, command=`npm run build:demo`).
2. GitHub Actions 로 배포한다면 Netlify **Site configuration → Build & deploy → Stop builds** 를 선택합니다.
3. 저장소 Secrets 에 다음 값을 등록합니다.
   - `NETLIFY_AUTH_TOKEN`: User settings → Applications → Personal access tokens
   - `NETLIFY_SITE_ID`: Site configuration → Site ID
4. 데모 계정 (Mock 전용, 실제 서버와 무관):

   | 구분 | 이메일 | 비밀번호 |
   |---|---|---|
   | 일반 사용자 | `user@jobpick.test` | `Jobpick!2026` |
   | 테스트 관리자 | `sandbox@jobpick.test` | `Sandbox!2026` |
   | 정식 관리자 (데모) | `admin@jobpick.demo` | `Admin!Demo2026` |

### 2단계 — 백엔드·RPA·AI 통합 로컬 검증

```bash
py -3.11 -m venv .venv                    # macOS/Linux: python3.11 -m venv .venv
.venv\Scripts\activate                    # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
copy .env.example .env                    # 값 채우기 (ADMIN_JWT_SECRET, ADMIN_INITIAL_* 등)
uvicorn backend.app.main:app --reload     # http://localhost:8000/docs
cd frontend && npm ci && npm run dev      # http://localhost:5173
python -m pytest -q                       # 백엔드·RPA 테스트
python -m rpa.run --all                   # 운영 수집 대상 전체 실행
```

- TiDB 연동 검증 시 `.env` 의 `DATABASE_URL` 을 TiDB 접속 문자열로 바꿉니다.
  - 예: `mysql+pymysql://...:4000/jobpick?ssl_ca=...&ssl_verify_cert=true&ssl_verify_identity=true`
- PDF 스캔본이나 이미지 OCR 에는 [Tesseract](https://github.com/tesseract-ocr/tesseract) 와 한국어 데이터(`kor`)가 필요합니다. Windows 는 `TESSERACT_CMD` 에 실행 파일 경로를 지정합니다.
- Playwright 수집기를 쓰려면 `playwright install chromium` 을 실행합니다.
- Docker 로 통합 실행: `docker compose up --build`
  - web: http://localhost:8080, api: http://localhost:8000
  - 수집 1회 실행: `docker compose --profile rpa run --rm rpa`

### 3단계 — Render 배포

1. Render 대시보드에서 **New → Blueprint** 로 저장소를 선택합니다. `render.yaml` 의 두 서비스(`jobpick-api`, `jobpick`)가 만들어집니다.
2. `jobpick-api` → Environment 에서 `sync: false` 항목을 직접 입력합니다.

   | 변수 | 설명 |
   |---|---|
   | `DATABASE_URL` | TiDB Cloud 접속 문자열 (무료 플랜 디스크는 휘발성이므로 SQLite 는 운영에 사용하지 않음) |
   | `ADMIN_INITIAL_EMAIL`, `ADMIN_INITIAL_PASSWORD` | 정식 관리자 초기 계정. 비밀번호 규칙 충족 필수. 첫 기동 시 1회 생성 |
   | `ADMIN_TOTP_SECRET` | 선택. 2단계 인증 |
   | `GEMINI_API_KEY` | 선택. 비우면 규칙 기반 엔진 |
   | `GOOGLE_*`, `NAVER_*`, `KAKAO_*` | 소셜 로그인 |
   | `WORKNET_API_KEY` | 고용24 Open API 인증키 |

   `USER_JWT_SECRET`, `ADMIN_JWT_SECRET` 은 Blueprint 가 서로 다른 임의 값으로 자동 생성합니다.
3. 각 서비스 **Settings → Deploy Hook** URL 을 복사해 GitHub Secrets 에 등록합니다.
   - `RENDER_API_DEPLOY_HOOK`
   - `RENDER_WEB_DEPLOY_HOOK`
4. 소셜 로그인 콘솔의 Redirect URI 는 `https://jobpick-api.onrender.com/api/auth/oauth/{google|naver|kakao}/callback` 입니다.
5. 운영 수집 스케줄은 두 가지 방법 중 하나로 설정합니다.
   - Render **Cron Job**: 명령 `python -m rpa.run --all`, 같은 환경 변수 사용
   - GitHub Actions `schedule`

## 3. CI/CD (`.github/workflows/deploy.yml`)

| 변경 경로 | 실행 작업 |
|---|---|
| `frontend/**`, `rpa/data/**`, `netlify.toml` | 프런트 빌드 2종 → Netlify 데모 배포 + Render 프런트 Deploy Hook |
| `backend/**`, `rpa/**`, `requirements.txt`, `render.yaml` | `pytest` 통과 시 → Render API Deploy Hook |
| `docs/site/**` | GitHub Pages 배포 |

- Pull Request 에서는 테스트와 빌드만 실행하고 배포하지 않습니다.
- 수동 실행(`workflow_dispatch`)에서 `deploy_all` 을 체크하면 모든 영역을 배포합니다.
- Render 서비스는 `autoDeploy: false` 입니다. 배포는 Actions 가 Deploy Hook 으로만 트리거하므로 영역별 개별 배포가 보장됩니다.

## 4. 운영 체크리스트

- [ ] `APP_ENV=production` 에서 `USER_JWT_SECRET` 이 기본값이면 서버가 시작되지 않는지 확인
- [ ] `ADMIN_JWT_SECRET` ≠ `USER_JWT_SECRET` 확인 (`/api/health` 의 `admin_login: true`)
- [ ] 정식 관리자 비밀번호 변경 후 `ADMIN_INITIAL_PASSWORD` 를 대시보드에서 삭제 (기존 계정 비밀번호는 덮어쓰지 않음)
- [ ] 운영 공개 전에 `ENABLE_TEST_ACCOUNTS=false`, `SEED_DEMO_HISTORY=false` 로 전환 검토
- [ ] 수집 대상 사이트의 이용약관·robots.txt 확인 후 등록
- [ ] Render 무료 플랜의 콜드스타트(첫 요청 지연)를 안내 — 프런트에 안내 메시지가 내장되어 있음

## 5. 장애 대응

| 증상 | 확인 사항 |
|---|---|
| 프런트에서 "서버에 연결할 수 없습니다" | Render API 슬립 상태(최대 1분), `CORS_ORIGINS` 에 도메인 포함 여부 |
| 정식 관리자 로그인 503 | `ADMIN_JWT_SECRET` 미설정 또는 `USER_JWT_SECRET` 과 동일 |
| 분석 결과에 "규칙 기반 결과" 안내 | Gemini 오류로 폴백된 상태 — `GEMINI_API_KEY`, 할당량, 모델명 확인 (관리자 대시보드의 "대체 처리" 수치) |
| OCR 422 | Tesseract 미설치(`TESSERACT_CMD`) 또는 텍스트 없는 파일 |
| 수집 실패 | 관리자 → 수집 관리 → 실행 이력의 오류 메시지 (robots.txt 차단, 인증키 누락, 타임아웃 등) |
